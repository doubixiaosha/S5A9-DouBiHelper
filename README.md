# DouBi Helper（S5A9）

DNF 私服（S5A9 / ARAD.EXE，32 位）的本地辅助工具。通过 OpenProcess + 远程内存读写 + 远程汇编执行实现自动拾取、装备处理、顺图、BUFF / 自动物品、本地 GM 与游戏内彩色公告。

界面为单窗口竖版布局（宽 400、高 880，可拉伸），自上而下：标题栏 → 角色信息区 → 四个功能卡片（自动捡物 / 装备处理 / 顺图 / 区域·特殊功能）→ 底部热键说明与运行日志。

## 技术栈与约束

| 项 | 取值 |
|---|---|
| 语言 / 框架 | 纯 C#，WPF，.NET Framework 4.8（`net48`） |
| 平台目标 | **x86**（`PlatformTarget=x86`），进程内强制校验 32 位，禁止 AnyCPU |
| 解决方案 | `DnfHelper.sln` 只有一个项目 `DnfHelper.UI` |
| 外部依赖 | 无第三方 UI 库、无 NuGet 包；全部逻辑在托管层进程内实现，无外部二进制模块 |
| 权限 | 启动即提权（`app.manifest` 声明 `requireAdministrator`） |
| 分发形态 | 绿色免安装，`build\<Configuration>\` 整个目录即绿色包 |

全部功能逻辑（内存扫描、远程 CALL、组包发送、循环线程）都在托管层进程内实现（`Core` 命名空间），无外部二进制模块；UI 只做低频开关、状态轮询与配置持久化。

## 功能与热键

热键由 `Services/HotkeyService.cs` 通过 `RegisterHotKey` 注册在窗口句柄上，**常驻注册**，是否响应由界面按功能开关判断。

| 热键 | 功能 | 说明 |
|---|---|---|
| `ALT+Q` | 自动拾取开关 | 等同点击捡物卡片的启用开关，切换后写配置并播报公告 |
| `ALT+F` | 装备处理 | 单次触发，不是开关；开关未开启或未附加时忽略并写日志 |
| `ALT+G` | 本地 GM | 单次切换权限补丁，切换成功才翻转状态并播报 |
| `ALT+1` | BUFF | 手动单次执行，是 BUFF 的唯一触发方式（无开关、无自动触发） |
| `ALT+2` | 自动物品 | 单次执行；开关只控制进副本的自动触发，不影响热键 |
| `ALT+方向键` | 顺图 | 左 / 右 / 上 / 下各执行一次当前选定的顺图方式；开关关闭时无响应 |

### 自动拾取

- 两种方式：**吸物拾取**（把地面掉落物的坐标改写为人物坐标，由游戏自身完成吸附）、**自动入包**（按掉落物 key 发送拾取包）。
- **仅在副本内（游戏状态 = 3）生效**：每轮先判状态，非副本直接静默返回，不写补丁、不发包、不打日志。
- 循环间隔固定 500ms（`Worker` 线程，每轮最多处理 64 个地面物品）。
- 吸物方式依赖游戏内自动捡物标志的 2 字节补丁（`0x02CA6F76`：`74 12` → `34 01`），该补丁只在副本内写入，离开副本即撤销；关闭功能时还原原字节。

### 装备处理

- 六个品质各一个处理动作：**白 / 蓝 / 紫 / 粉 / 史诗 / 传说**，取值 **不处理 / 卖物 / 分解**（每行三选一互斥单选，改动即时写配置并下发）。
- **单件豁免**：装备栏 56 格按槽位 1..56 对应，勾选即该单件跳过；列表只展示扫描到装备的行，表头右侧带「刷新」按钮。
- **异界品质（quality = 5）不处理**；紫装名称含「传承」保留不处理。
- 收尾固定发送一次整理背包包（CMD 20）。
- 触发方式：
  - 自动：仅在**副本 → 城镇**的状态边沿触发，延迟 **1.5s** 后先直读游戏状态，必须是城镇（1/2）才执行；切回副本会作废待执行的装备处理。
  - 手动：`ALT+F` 立即执行，不做状态校验。

### 顺图

- 四种方式：**组包顺图**、**强制顺图**、**瞬移顺图**、**移动顺图（占位，未实现）**。
- 组包：读当前房间坐标并按网格通道字节判定该方向可通行后，发送 CMD 45（100 字节定长包）。
- 强制：直接 CALL 强制过图函数（ecx = 房间上下文，栈参 = 方向 / 格 X / 格 Y / 强制标志 1）。
- 瞬移：要求当前房间门为开启状态，读目标方向房间矩形，先瞬移到门外 20px 处，等待 200ms，再瞬移到房间中点。
- 移动方式仅保留入口：选择会被保存，执行时只写一条「顺图未执行」日志，不做任何动作。

### BUFF / 自动物品

- **BUFF**：只能 `ALT+1` 手动执行一次，没有开关，也不参与自动触发；界面上该行只有标题、说明和编辑框。
- **自动物品**：开关打开时，进入副本后 **1.5s** 自动触发一次（执行前再次直读状态确认仍在副本）；`ALT+2` 可随时单次触发，不受开关影响。
- 参数分别是**游戏侧 BUFF 类型编号**与**物品 ID**，逗号 / 空格 / 分号分隔，解析时去重并丢弃非正数。
- 每个编号一次远程调用，两次调用之间至少间隔 **50ms**，单次调用超时 3000ms；同一功能同一时刻只跑一轮（busy 标志）。
- 均为一次性触发，不做周期循环。

### 本地 GM

- 在 `0x016F8020` 写入 16 字节权限桩：`cmp ecx,[角色对象指针槽] / jz +3 / xor al,al / ret / mov al,1 / ret / int3;int3`，使权限检查对当前角色恒返回真。
- 首次写入前备份原字节，关闭时写回；附加断开、切换目标进程、程序退出都会无条件还原。
- 角色槽为空时补丁虽写入但不会命中，此时会额外提示「尚未进入角色，GM 权限可能不生效」。

### 彩色公告

- 直接 CALL 客户端公告函数 `0x02E2C9E0`（thiscall：`ecx = [[0x062EF53C] + 0x54]`，栈参 = 结构体指针 − 4），不发送聊天 / 喇叭包。
- 固定口径：**前缀 `[DouBi] `、无图标、颜色固定绿色（`0x0000FF00`）、类型 37**。
- 发送内容：各功能开关切换、手动热键执行（含 `手动BUFF 已执行`）、自动物品的自动触发、附加后首次进入可玩状态时的当前时间 `HH:mm:ss`。
- 异步发送（线程池），与上一条至少间隔 500ms；未附加 / 未进入角色静默跳过，失败只告警一次。

### 附加与状态显示

- 启动后按进程名 `ARAD.EXE`（大小写不敏感）自动查找并附加；失败不弹阻塞对话框，只在状态栏显示原因并写日志，可点「重连」重试。
- 游戏进程退出后自动分离并提示重连。
- 1 秒轮询一次状态：角色信息行（名称 / 等级 / 职业 / 当前状态）、位置行（城镇 ID / 区域 ID / 坐标，或副本 ID / 副本名称）、房间行（当前房间坐标与 BOSS 房间坐标，仅副本内可见）。

## 配置文件

- 位置：与 `DnfHelper.UI.exe` 同目录的 **`DouBi.ini`**，UTF-8（无 BOM），不依赖系统 ANSI 代码页。
- **由程序运行期自动生成**：文件不存在时首次启动即按默认值创建；该文件属于用户运行期数据，**不纳入版本库**，仓库不提供 ini 模板文件。
- 文件损坏时按内置默认值运行，下次保存重建。
- 段名、键名、取值全部为中文，**只认中文**：不读取任何英文段/英文键，也不接受数字形式的枚举值。旧 ini 里的残留键在下次保存时自然丢弃。
- 取值白名单：布尔 `是/否`（其他写法按默认值处理）；主题 `深色/浅色`；捡物方式 `吸物/自动入包`；顺图方式 `组包/强制/瞬移/移动`；装备动作 `不处理/卖物/分解`。
- 缺失的段/键、无法识别的取值一律回落到内置默认值，不报错、不中断启动。

**只持久化下列内容**：主题；捡物启用与方式；装备处理启用与六品质动作；顺图启用与方式；BUFF 类型列表；物品 ID 列表。

**不持久化**（每次启动为默认 / 关闭状态）：自动物品的开关、捡物折叠区展开状态、装备豁免 56 格勾选、扫描间隔、窗口尺寸。BUFF 没有开关，其类型列表随 `[特殊功能] BUFF类型` 持久化。

```powershell

dotnet build DnfHelper.sln -t:Rebuild -c Debug -p:Platform=x86
```

或用 Visual Studio 打开 `DnfHelper.sln`，选 **Debug|x86** 生成。

- 产物：`build\Debug\DnfHelper.UI.exe`（Release 为 `build\Release\`）；`build\obj\ui\<Configuration>\` 为中间目录。
- 解决方案只暴露 `Debug|x86` / `Release|x86` 两个配置组，`PlatformTarget` 固定 x86。
- 运行前提：Windows + .NET Framework 4.8 运行时；目标游戏为 **32 位 `ARAD.EXE`**，且客户端版本与 `Core/Shared/GameAddresses.cs` 的地址表匹配。

## 实现要点

### 远程执行

`RemoteExecutor` 是全部 CALL / 组包的统一出口：

1. `VirtualAllocEx` 申请 RWX 内存，长度按 16 字节对齐、不足 4KB 补到 4KB；
2. 写入机器码后 `CreateRemoteThread`，`WaitForSingleObject` 等待；
3. 线程收尾用目标进程的 `ntdll!RtlExitUserThread`（本进程导出地址减本进程 ntdll 基址得 RVA，再加目标 ntdll 基址）；
4. `VirtualFreeEx` 释放。

全局锁保证任一时刻只有一条远程线程；`minGapMs` 参数用于拉开连续调用（BUFF / 物品固定 50ms）。超时后最多再等 5s，仍不退出则保留内存不释放，避免释放正在执行的代码页。

### 编解码

`Codec.SuperDecrypt` 读 8 字节槽位：`[addr]` 为加密 ID、`[addr+4]` 为密文，按 `DecryptBase` 指向的密钥表两级查表得到 16 位密钥，`mask = (k << 16) | k`，明文 = `mask ^ 密文`；任一环节读到 `0xFFFFFFFF` 返回 -1。门状态、掉落 key、物品数量、地图索引、BOSS 房间坐标都必须走此算法。

### 组包

`PacketSender.Send(head, fields)` 在一次远程执行中完成 `BeginPacket(head, 0)` → 逐字段 `Encrypt`（宽度 1/2/4 对应入口偏移 0 / +48 / +96）→ `Send`；字段宽度只允许 1/2/4，非法直接返回失败。当前使用的 CMD：20 整理背包、22 卖物、26 分解、43 拾取（20B）、45 移动房间（100B 定长）。

### 状态触发（边沿检测）

不新增轮询线程，全部挂在 `MainViewModel` 的 1 秒 `DispatcherTimer` 上：

- 只在 `GameState` 数值变化时触发一次；首次采样只建立基线，若首次即为副本则按「切入副本」处理。
- 非副本 → 副本(3)：延迟 1500ms 执行自动物品。
- 副本(3) → 城镇(1/2)：延迟 1500ms 执行装备处理。
- 两条延迟链独立：切入副本作废待执行的装备处理，离开副本作废待执行的自动物品；快速反复进出只有最后一次生效。
- 延迟到点后先 `CoreBridge.CurrentGameState()` 直读最新状态做最终校验，不符则静默丢弃，不补发。
- 触发一律投递线程池执行，不阻塞 UI 线程。

### 公告

结构体与文本缓冲都在游戏进程内 `VirtualAllocEx` 申请并长期持有（按 PID 校验复用，断开时释放），注入 stub 执行 CALL。结构体 204 字节：`buf[0]` 文本指针、`buf[4]` 颜色、`buf[5]` 类型、`buf[9]` 图标指针（本次置 0）。文本为 UTF-16LE、整块覆盖写入。

### 线程模型

- 每个循环功能一个 `Worker` 后台线程（自动拾取 500ms、装备处理 25ms 轮询请求位、顺图 25ms 轮询方向位），`Stop` 可中断等待并 Join。
- `CoreRuntime` 维护一条**全局序列锁**：BUFF 序列与物品序列（含进副本自动物品）共用同一把锁，整个序列期间独占。任意时刻只跑一条，后到的一条直接丢弃并记日志 `BUFF 正在执行，已忽略` / `物品 正在执行，已忽略`；序列结束后释放。
- 单次动作（BUFF / 物品 / 公告）投递线程池；公告不参与该序列锁。
- 日志由 `CoreLog.Message` 事件发出，同时写 `OutputDebugString("[DouBiHelper] …")`；UI 侧统一切回 Dispatcher 再入日志集合。

## 已知限制与风险

- **移动顺图为占位**：选择会保存，执行时不做任何动作，只写一条「顺图未执行」日志。
- **地址硬编码强依赖客户端版本**：全部常量集中在 `Core/Shared/GameAddresses.cs`，换客户端需整表核对，否则功能会静默失败或读到错误数据。
- **彩色公告走远程线程而非游戏线程**：直接在目标进程新线程中 CALL 公告函数。若出现异常（游戏卡顿、崩溃或公告不显示），应改为在游戏线程派发。
- **背包 / 金库只读扫描无界面入口**：`ScanBag` / `ScanVault` 能力保留在 Core，但存仓功能已整体移除，界面没有对应窗口。
- **装备豁免不持久化**：56 格勾选每次启动为空，扫描后需重新勾选。
- 捡物过滤（黑白名单）已移除，当前只有「吸物 / 自动入包」方式选择。
- 自动物品的开关不持久化，每次启动需手动打开（`ALT+2` 单次触发不受开关影响）；BUFF 无开关，仅 `ALT+1` 手动执行。
- 远程线程超时后若游戏函数长期不返回，保留的内存页不会被回收（刻意设计，避免释放正在执行的代码）。
- `build\Debug\DouBi.ini` 可能是旧版英文键格式：其中英文段/键与数字枚举全部被忽略，相关配置按默认值运行，下次保存会被整体改写为中文键格式。
